# Natural applicability of equal-domain search proofs

The first proposed content-invariance path would discharge text obligations for
an ambiguous correspondence component only through an independently validated
equal ordered domain. Before changing search semantics, this audit screens the
existing natural reports for a necessary condition: all proposal nodes in an
exhaustively searched, nonempty component with no mandatory edge must fit inside
one proved-equal whole-node native interval on both sides.

`content-invariance-v1.json` binds the read-only audit and every report. The snapshot
combines the previous complete 36-pair capture, the five lookup-fix pilot pairs and
a fresh Llama 2 capture using that exact frozen lookup-fix executable and fixed
inputs, arguments and budgets. It is not a new full-panel execution.

| Observation | Count |
| --- | ---: |
| Equal whole-node native intervals | 37 |
| Nonempty components with no mandatory edge | 3,169 |
| Of those, component search exhaustive | 3,138 |
| Exhaustive ambiguous components enclosed by one equal interval | 1 |

The one candidate is Llama 2 scope 0, component 413. Four literal-content proposals
match two repeated occurrences each way. Boundaries 5114/5128 enclose four nodes
and 18 native references on each side. The scope selects text only and conflict
search is complete, but text candidate enumeration is incomplete. Report-local
indexes identify this observation only; they must never become implementation
rules. Enclosure is not a trusted deserialized certificate or proof that all
candidate, relationship, inventory or whole-document obligations are discharged.

The fresh Llama run also measures a further effect of the previous lookup reuse
fix: 15 additional equal intervals and 113 additional compared references per
side, from 102,337 to 102,450. Every earlier interval is retained and the remainder
of the comparison object is identical. This is reported source coverage, not
independent transcription adjudication, fixed-target recovery or new completion.

## Consequence for implementation priority

Keep the current solver and search result unchanged. This first equal-domain
consumer has only one observed natural component to investigate, and that scope
retains other unfinished work. It is not a demonstrated route to two complete
natural pairs. Prioritize the acquisition/interpretation proof gap instead of
implementing a broad search-success exception around the repeated-text fixture.

This screen excludes partial cuts, unions of certificates, changed domains and
incomplete components. It says nothing about the applicability of future domains
with independently proved acquisition, order and scope. It does not establish
that ambiguity always prevents content proofs. The original strict completion
goal remains unmet; no production behavior or completion contract changes here.
